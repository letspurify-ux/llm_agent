# 중첩 콘텐츠의 셀 소유 범위 검토 — 2026-09-09

## 추가로 재현한 문제

행 단위 격리만으로는 같은 행의 다른 셀을 보호하지 못했다. 다음 표 행의
첫 백틱이 다른 셀의 백틱과 짝을 이루어 정상 수식과 조회 주입이 누락됐다.

```markdown
| `ordinary | $z^2$ | `chart\ndata:step1` | ` |
```

이미지·HTML의
미완성 기호도 같은 문제를 일으켰다. 수식 머리글 때문에 첫 GFM 파싱이 표를
놓친 경우에는, 이미 주입한 차트의 내부 개행까지 바깥 문서 개행으로 바뀌었다.

미완성 `$$`·`\(`·`\[`와 다른 셀의 Mermaid·수식을 함께 놓으면
Mermaid 라벨의 `$$`를 바깥 수식의 닫는 기호로 빌리거나, 시각화 전체를
바깥 오류 수식에 포함하는 경로도 있었다.

별도로, 직렬화 개행 다음의 `u`, `eq`, `ewcommand` 등은 TeX 명령 이름
목록과 우연히 일치하면 복원되지 않았다. 표의 첫 셀뿐 아니라 Mermaid 노드
ID와 차트 데이터 행에도 영향을 주었다. 한 개·두 개 대시로 된 정상 GFM 표
구분 행을 직렬화하면 표 복원이 실패하는 경우도 재현했다.

## 공통 설계

- `shared/rich-table-structure.mjs`는 수식·명시적 시각화 후보의 파이프를
  원문과 같은 길이로 가린 구조 투영을 만든다. 실제 표 구조는 GFM이 판정한다.
- 후보 단계에서 아직 잘린 GFM 셀이나 문서 전체의 백틱 짝을 최종 소유자로
  간주하지 않는다. 투영으로 발견한 **각 셀을 원문에서 다시 읽고** 주소·HTML·
  일반 코드·참조 정의가 소유한 후보를 제외한다. 표시 값에는 투영 문자를 쓰지 않는다.
- `tableOwnership`은 행 밖의 원문 노드를 유지하고 셀 내부 원자만 다시 분석한다.
  참조 정의를 공유하며, 셀의 `#`·`>`·들여쓰기를 새 바깥 블록으로 읽지 않는다.
- 서버는 같은 셀 좌표 안에서 조회 코드를 찾는다. 화면의 시각화 보호도 같은
  셀 경계를 사용한다. 정상 조회 문자열·숫자와 이웃 셀이 함께 보존된다.
- 수식 분석은 초기 AST의 수식 노드도 검증한다. 시각화 내부에서 끝난 수식은
  유효한 짝이 아니다. 완성된 TeX 인자 안의 코드 예시는 원문으로 유지한다.
  앞 단계에서 시각화를 임시 토큰으로 바꿔도 그 범위를 다음 수식 분석에 전달한다.
- 개행 복원에도 같은 물리적 표 구조 분석을 적용한다. TeX 범위 밖의 직렬화
  개행을 명령 이름으로 제외하지 않는다. 시각화 내부 수식은 언어 범위로 보호하고,
  추가 이스케이프를 복구하는 TeX 본문에서는 제어 단어 전체를 한 토큰으로 읽는다.
  수식 양끝의 직렬화 개행은 본문을 읽기 전에 벗겨, `\nx=...`의 첫 개행과
  CRLF의 `\r`이 명령으로 남지 않게 한다. 기존 `N_COMMAND` 예외 목록은 제거했다.

## 회귀 검사

새 `frontend/test/cell-ownership.test.js`는 다음을 확인한다.

- 원자 10종 × 바깥 컨테이너 5종 × 가장자리 파이프 4종 × 내용 순서 2종 ×
  실제·직렬화 개행 5종: **2,000개**. 셀 수뿐 아니라 수식 원문, Mermaid 원문,
  차트 제목·조회 문자열·숫자, 오류 원문과 미리보기 결과를 대조한다.
- 수식·시각화 머리글과 원자 6종의 조합 및 실제 개행·직렬화 결과 대조.
- 첫 셀 단어 7종, 구분 행 4종, 가장자리 4종, 컨테이너 5종,
  직렬화 2종: **1,120개**. `\nu`와 `\nleqq`의 TeX 원문도 함께 보존한다.
- 뒤 셀을 수신하는 접두사, 시각화의 행 시작 단어, 알려지지 않은 TeX 제어 단어.

실제 앱의 `serialized-boundaries` 그룹에는 기존 행 경계 20회에 셀 경계
20회와 제어 단어·짧은 구분 행 2회를 추가했다. 1,000px·320px에서 실제 차트,
SVG·MathML, 중첩 목록·인용, 라벨 폭, 이웃 셀의 스크롤 도달과 콘솔을 검사한다.
그림 대기는 다른 셀의 수식 오류가 아니라 **필요한 SVG가 모두 게시된 상태**를
확인한다. 기존 150회 그룹, 판정 조건과 제한 시간은 유지한다.

```sh
npm --prefix backend test
npm --prefix frontend run test:regression

node frontend/test/review/rendering-browser.mjs --group=serialized-boundaries
```

모든 원문이 문법적으로 유효한 것으로 가정하지 않는다. 미완성·미지원 입력은
원문으로 확인할 수 있게 남기고, 이웃의 정상 콘텐츠를 보존한다. 실제 DB·LLM을
호출하지 않고 고정 조회와 응답을 사용해 서버 주입부터 실제 렌더까지 검증한다.

## 검증 이력

초기 셀 경계 검토에서 전체 백엔드 574개, 집중 단위 68개와 새 셀 경계 4개,
개발 화면 40회가 통과했다. 이후 수신 끝의 원자 소유권과 인라인 수식 배치를
보완했고, 전체 셀 수신 접두사 검사가 통과했다. 최종 코드와 해시를 대조한
통합 결과는 [완료 검토 기록](nested-rendering-follow-up.md)에 정리한다.
