# 중첩 문법 경계 추가 검토 — 2026-09-09

기존 중첩 렌더링 변경을 유지하면서, 개행 복원 → 시각화 보호 → 수식 파싱 → 실제 렌더와 서버 조회 주입 사이의 경계를 추가 검토했다.

## 재현한 문제와 수정

| 조합 | 수정 전 결과 | 수정 |
|---|---|---|
| 문자로 남은 `\n` → Markdown 표 → Mermaid/차트의 내부 파이프 | 개행 복원으로 새 표가 만들어졌지만 보호 단계는 이미 끝나 있어 오른쪽 셀과 그림 본문이 잘림 | 개행 복원 이후의 AST에서 시각화 구간을 보호 |
| 문자로 남은 `\r\n` → 표 → LaTeX·Mermaid | 문자 `\r`이 구분 행에 남아 표 전체가 일반 문단으로 표시됨 | 직렬화 CRLF를 하나의 개행으로 복원. 코드·주소의 원문은 기존대로 보호 |
| LaTeX → `chart<br>data:step1` 코드 예시 | 서버가 수식 본문에 조회 표를 주입해 정상 수식이 오류 폴백으로 바뀜 | 화면의 수식 범위 탐색을 공통 모듈로 분리하고 서버에서도 사용 |
| 각주 이름 → chart 코드 예시 | 참조 이름만 조회 결과로 바뀌어 정의와 연결이 끊어짐 | GFM 각주를 분석해 참조·정의 이름을 보호. 각주 본문의 실제 차트는 정상 처리 |
| 들여쓴 코드·HTML·주석 → chart/table 펜스 예시 | 예시가 조회 대상으로 치환되고 HTML 안의 코드가 밖으로 나오는 경우도 발생 | Markdown AST가 확인한 닫힌 코드 펜스만 주입 대상으로 선택 |
| 목록·인용·각주 → 공백이 다른 정상 펜스 | 고정된 접두사 비교 때문에 정상 조회를 놓침 | 파서가 읽은 코드 본문과 실제 컨테이너 접두사를 사용해 원래 위치에서 치환 |
| 주소·HTML 속성·참조 이름의 백틱 + 이웃 Mermaid/차트 | 주소의 백틱이 이웃 코드의 시작 기호를 닫는 기호로 소비해 그림과 오른쪽 셀이 잘림 | 리터럴 영역의 백틱을 먼저 제외한 다음 같은 길이끼리 짝을 연결 |

서버와 화면이 공유하는 수식 탐색은 [math-spans.mjs](../shared/math-spans.mjs), 백틱 경계는 [inline-code.mjs](../shared/inline-code.mjs)에 있다. 기존 프런트엔드 수식 모듈의 공개 경로는 재내보내기로 유지했다. 서버에는 프런트엔드와 같은 GFM·수식 파서 확장을 명시적 의존성으로 추가했다.

문법 기준은 [GFM 코드 펜스 규칙](https://github.github.com/gfm/#fenced-code-blocks)과 설치된 [mdast GFM 확장](https://github.com/syntax-tree/mdast-util-gfm#use)을 확인했다. 코드 펜스처럼 보이는 문자열인지와 실제 파서가 코드 블록으로 읽었는지를 구분하는 것이 수정의 기준이다.

## 추가 회귀 검사

- 직렬화된 표 96개: 시각화 2종 × 내부 개행 4종 × 백틱 길이 3종 × 서식 2종 × 바깥 개행 2종. 각각 최종 렌더와 스트리밍 미리보기를 검사한다.
- LaTeX와 서버 조회의 중첩 40개: 구분자 4종 × 성공/실패 명령 2종 × 목록·인용 래퍼 5종. 정상 수식과 오류 원문의 정확한 보존을 확인한다.
- 주소·속성·참조 이름과 이웃 시각화 60개: 백틱 길이 3종 × 시각화 2종 × 리터럴 5종 × 배치 방향 2종.
- 정상 컨테이너 24개와 코드·HTML·미완성 펜스 예시 48개. 실제 개행 LF·CRLF·CR을 포함한다.
- 각주 참조와 본문, 스트림의 모든 접두사, 앞에서 완성된 수식과 이웃 셀 보존을 별도로 확인한다.
- 배포 앱 검사에 직렬화 표·LaTeX/각주 안의 chart·공백이 다른 목록/인용/각주를 추가했다. 1,000px와 320px에서 차트, SVG, MathML, 셀 내용, 각주 연결, 페이지 넘침, 콘솔, 임시 토큰을 검사한다.

추가 테스트는 [프런트엔드 문법 경계 검사](../frontend/test/syntax-ownership.test.js), [백엔드 문법 경계 검사](../backend/test/markdown-syntax.test.js), [실제 앱 검사](../frontend/test/review/rendering-browser.mjs)에 있다. 기존 1,080개 중첩 조합, 수식 표 200개, 표 링크 180개, 오류 격리·스트리밍·리셋·재시도·인쇄 검사도 유지했다.

## 실행

```sh
npm --prefix backend test
npm --prefix frontend run test:regression
```

검증 결과: 백엔드 567개, 프런트엔드 단위 검사 305개, Chrome UI 검사 87개,
배포 빌드 검사 3개가 통과했다. 배포 검사에는 14개 실제 앱 사례를 두 화면 폭에서
검증하는 28회 조합 검사가 포함된다. 마지막 백틱 경계 변경 후 백엔드 관련 검사
39개도 다시 통과했다. `git diff --check`도 통과했다.

첫 전체 화면 검사에서는 스크롤 검사의 사전 조건(화면에 보이는 표)이 성립하지 않아
1건 실패했다. 최종 소스를 고정한 전체 재실행에서 해당 검사와 나머지 86개,
이어지는 배포 검사까지 모두 통과했다. 테스트 조건이나 대기 시간은 완화하지 않았다.

실제 DB·LLM은 호출하지 않고 고정 응답과 조회 결과를 사용한다. KaTeX·Mermaid 자체의 미지원 문법은 기존 원문 폴백으로 확인할 수 있다.
