# 중첩 렌더링 완료 검토 기록 — 2026-09-09

아래는 직렬화 표 수정 뒤 진행한 완료 검토에서 발견한 항목과 당시의 측정 기록이다.
긴 인라인 수식은 이후 [배치 개선](inline-math-layout-review.md)으로 수정했다.
공통 소유권 규칙과 전체 구조 변경을 합친 최종 소스에서 단위·개발·배포·인쇄
회귀 검사가 모두 통과했다. 최종 결과는 문서 끝에 기록했다.

## 공통 설계와 불변 조건

문자열별 예외 목록 대신 다음 계약을 서버·미리보기·최종 렌더링에 적용한다.

| 단계 | 공통 규칙 |
|---|---|
| 구조 발견 | 내부 언어의 구분자를 같은 길이로 가린 투영에서 GFM이 컨테이너·행·셀을 판정한다. |
| 원문 소유권 | 확정된 셀을 원문에서 읽는다. 수식·코드·주소의 값과 치환 위치는 원문 좌표를 사용한다. |
| 원자 경계 | 모든 범위는 `[start, end)`다. 원자가 소유한 첫·마지막 문자를 바깥 수식의 구분자로 사용할 수 없다. |
| 중첩 언어 | 완성된 TeX 인자 안의 코드 모양 문자는 그 인자가 소유한다. 시각화 후보에는 실행 권한이 없다. |
| 수신 중 복구 | 불완전한 원자는 완성된 이웃 원자·셀을 가져가지 않는다. 뒤의 입력이 더 도착해도 앞의 완성된 콘텐츠는 유지한다. |
| 문법 해석 | 표·목록 등 Markdown 문법의 우선순위는 GFM에 맡긴다. 명령 이름·특정 머리글을 예외로 나열하지 않는다. |
| 화면 배치 | 문법 분석과 분리해 실제 컨테이너 폭을 측정한다. 넓은 인라인 수식만 스크롤하며 짧은 수식 배치는 유지한다. |

수식의 원자 충돌 판정은 `shared/math-spans.mjs`의 한 함수로 모았다. 첫 AST의
수식 노드와 이후 원문 스캐너가 동일한 판정을 사용한다. 이전에는 수신 조각의
끝과 원자의 끝이 일치할 때 두 경로의 포함 조건이 달라, Mermaid 내부의 마지막
`$$`가 앞 셀의 미완성 수식을 닫았다. 반개방 구간의 마지막 문자 소유권을 공통으로
적용한 뒤 전체 셀 수신 접두사 검사와 관련 수식·Mermaid 검사 144개가 통과했다.

배포 검사에서 발견한 짧은 구분 행 사례는 원래 GFM에서도 목록으로 읽히는
`- | -`를 표로 기대한 입력 오류였다. 독립 GFM 파서와 대조하고, 실제 표를 뜻하는
`| - | - |`로 검사 입력을 수정했다. 제품 파서의 문법 우선순위는 변경하지 않았다.
수정한 입력의 1,000px·320px 배포 화면 검사는 모두 통과했다.

## 수정 전 긴 인라인 수식의 잘림

수정 전 CSS는 `.md .katex`의 인라인 레이아웃을 유지하고, 말풍선의
`overflow-x: clip`으로 넘치는 내용을 자른다. 이 동작은 기존 README와 CSS
주석에도 명시되어 있었다. 실제 앱에 다음 답변을 주입해 320px에서 재현했다.

```markdown
짧은 수식 $x^2$ 뒤.

> 1. 긴 수식 $\frac{\text{ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ}}{\sqrt{x^2+y^2}}$ 끝.

[링크의 긴 수식 $\frac{\text{ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ}}{\sqrt{x^2+y^2}}$](https://example.test)
```

측정 결과:

| 위치 | 수식 폭 | 사용 가능한 폭 | 현재 수식 스크롤 |
|---|---:|---:|---|
| 인용 → 목록 | 505.28px | 168px | 없음 |
| 링크 → 수식 | 505.28px | 본문 268px | 없음 |

수식은 각각 오른쪽 591px·531px까지 뻗지만 말풍선 오른쪽은 308px이다.
따라서 페이지 넘침이 0이어도 수식의 뒷부분은 읽을 수 없다.

코드 변경 없이 브라우저에만 `inline-grid; max-width:100%; overflow:auto`를
적용했을 때 각각 168px·268px의 스크롤 영역이 생겼다. 그러나 모든 수식에
이를 적용하면 짧은 수식도 높이가 20px에서 약 41px로 바뀌어 문장 간격을
늘렸다. `inline-block`도 기준선·행 높이가 바뀌었다. 단순 전역 CSS 치환은
최종 해결로 채택하지 않았다.

후속 수정은 넘치는 수식만 실제 컨테이너 폭에 맞는 스크롤 영역으로 처리하고,
짧은 수식의 기준선·행 높이, 큰 분수·근호의 세로 글리프, 링크, 표의 기존
스크롤, 화면 리사이즈, 스트리밍·리셋·인쇄를 검증해야 한다. 현재 렌더 연결은
`App.jsx`의 `MAIN_MD`·`PREVIEW_MD`와 `ReactMarkdown`이며, 수식 HTML 생성은
`src/math.js`의 `rehypeMath`에 모여 있다.

로컬 재현 스크립트와 측정 결과는 각각 `/tmp/llm-agent-inline-probe.mjs`,
`/tmp/llm-agent-inline-probe.json`에 있고, 화면은
`/tmp/llm-agent-inline-original-320.png`에 있다. 스크립트가 띄운 서버와 Chrome은
종료 후 정리되었다. 저장소의 렌더링 코드는 이 측정으로 변경되지 않았다.

## 배포 교차 조합 1회 실패

`npm --prefix frontend run test:regression`의 최종 실행에서는 백엔드 경계
149개·프런트엔드 단위 340개·Chrome UI 88개가 통과했다. 배포 검사 4개 중
새 직렬화 그룹·실제 앱 전체 렌더·CSP의 3개는 통과했고, 기존 교차 조합은
150회 중 1회 실패했다. 다른 테스트의 통과로 이 실패를 덮지 않는다.

로그는 `/tmp/llm-agent-rendering-final.log`에 있다. 큰 JSON이 Node의 오류
출력에서 잘려 실패 사례의 식별자가 보이지 않아, 같은 소스를 직접 다시 실행해
`/tmp/llm-agent-production-core-audit.json`에 전체 결과를 보관한다.
실패 식별과 원인 확인 후 필요한 수정 및 배포 검증을 완료해야 한다.

직접 재실행에서는 `table-structure-unclosed-code/1000`의 Mermaid 대기가 만료됐다.
그 사례만 실행한 `/tmp/llm-agent-production-unclosed-audit.json`은 두 화면 폭 모두
통과했다. 검사에는 실패 시 DOM·코드 원문·페이지 가시성·콘솔 기록과, 큰 stdout과
별도로 실패 식별자·판정값을 남기는 진단을 추가했다. 검사 조건이나 제한 시간은
완화하지 않았다. 이어서 다른 브라우저 작업을 띄우지 않고 실행한
`/tmp/llm-agent-production-isolated.log`에서는 기존 150회와 새 20회 조합이 통과했다.

## 동시 변경과 검증 범위

완료 검토에서 시작 때 기록한 SHA-256과 현재 소스를 대조하자, 이 작업이 추가로
수정하지 않은 파일 다섯 개가 바뀌어 있었다. 앱 상태와 변경 기록에서 같은 폴더의
별도 활성 작업이 셀 단위 소유 범위 확장을 진행 중임을 확인했다.

- `shared/rich-table-structure.mjs`: 원문 소유 범위를 행에서 셀로 확장하고,
  시각화 후보의 구조 발견과 실제 리터럴 판정을 분리.
- `shared/serialized-markdown.mjs`: 구분 행 대시 개수는 GFM에 맡기고, 수식
  범위 바깥의 문서 개행을 TeX 명령 이름으로 제외하지 않음.
- `frontend/src/remark-rich-table.js`: 시각화 후보를 셀별로 처리.
- `backend/src/markdown-syntax.js`, `backend/src/chart.js`: 셀 좌표를 제공하고
  그 범위 안에서 조회를 주입.

이 변경은 보존했으며, 이 작업의 직렬화 경계·공통 TeX 그룹·회귀 검사도 남아 있다.
동시 수정 중의 서로 다른 파일 상태를 하나의 최종 검증 결과로 합치면 안 된다.
현재 구조 수정이 안정된 뒤 전체 회귀 검사를 다시 실행하고 소스 해시를 대조해야 한다.
현재 소스의 백엔드 문법 검사 9개는 통과했다.

## UI 검사 준비 단계 보완

통합 실행에서 기존 표 스크롤 검사의 준비 조건인 “바닥에 보이는 조회 표가 있다”가
한 번 실패했다. 스크롤 동작 판정에 도달하기 전의 실패이며, 단독 실행은 통과했다.
고정된 900ms·500ms 대기를 표가 실제로 펼쳐지고 화면 위치가 안정된 상태 확인으로
바꿨다. 바닥 도달, 표의 가시 범위와 기존 스크롤 판정 기준은 유지하고, 실패 시
표·대화의 좌표와 페이지 가시성을 남긴다. 보완 후 단독 검사도 통과했다.

별도 검사들이 같은 `ui-probe.html`을 덮어쓰거나 먼저 끝난 검사가 다른 실행의
페이지를 지울 수 있는 구조도 없앴다. UI 임시 HTML은 실행 프로세스별 이름을
사용한다. 같은 소스의 전체 회귀 결과를 아래에 기록한다.

## 최종 통합 검증

```sh
npm --prefix backend test
npm --prefix frontend run test:regression
```

두 명령 모두 종료 코드 0으로 완료했다.

| 검사 | 통과 | 실패·취소·건너뜀 |
|---|---:|---:|
| 백엔드 전체 | 574 | 0 |
| 프런트엔드 단위 | 347 | 0 |
| Chrome UI 전체 | 88 | 0 |
| 새 배포 빌드 | 4 | 0 |
| 긴 인라인 수식 개발·배포 | 2 | 0 |

필수 회귀 명령의 백엔드 전송·차트·문법 검사 149개도 통과했다. 배포 검사에는
기존 150회와 추가 42회 실제 화면 조합이 포함된다. 마지막 두 검사는 긴 수식의
양 끝 도달, 화면 크기 변경, 부분 스트림·완료, 인쇄·화면 복귀와 초기화를 확인한다.

실행 전 기록한 소스·테스트·설정 133개 파일의 SHA-256을 종료 후 대조했다.
변경되거나 새로 추가된 소스·테스트는 없었다. `git diff --check`도 통과했다.
중간 실행의 실패를 제외한 통과 수치를 조합한 것이 아니라, 위 최종 명령 전체가
동일한 파일 상태에서 통과한 결과다. 앞 절의 실패·재현은 수정 과정의 이력이다.
