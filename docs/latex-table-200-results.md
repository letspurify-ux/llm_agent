# Markdown 표 안 LaTeX 수식 200개 검증

수식 **200/200개 정상 표시**, **200행·800셀 보존**, 해당 표의 렌더링 오류 **0개**를 확인했다.

## 테스트 입력

- [실제 Markdown 표](../frontend/test/fixtures/latex-table-200.md): 하나의 표에 수식 200개, 번호·분야·수식·행 확인의 4열.
- [코퍼스 원본](../frontend/test/latex-table-200.js): 대수, 근호, 분수·절댓값, 삼각함수, 로그, 극한, 미분, 적분, 급수, 행렬, 벡터, 확률, 통계, 집합·논리, 복소수, 특수함수·물리, 다중 행, 정렬·구간, 화학식, 단위·문자 조판의 20개 분야에 각각 10개.
- 200개 수식의 원문은 모두 서로 다르다. 숫자만 바꿔 반복한 입력을 사용하지 않았다.
- 일반 달러, 앞뒤·한쪽 공백이 있는 달러, 소괄호·대괄호 구분자, 이중 달러와 ASCII 백슬래시·원화 표기를 섞었다. 절댓값과 행렬의 raw 파이프도 그대로 넣었다.

## 결과

| 검증 경로 | 정상 수식 | 행 / 셀 | 수식 오류 |
|---|---:|---:|---:|
| 실제 ReactMarkdown·KaTeX 렌더링 | 200 / 200 | 200 / 800 | 0 |
| 개발 UI, 데스크톱 1000px | 200 / 200 | 200 / 800 | 0 |
| 개발 UI, 모바일 380px | 200 / 200 | 200 / 800 | 0 |
| 스트리밍 미리보기 | 200 / 200 | 200 / 800 | 0 |
| 스트리밍 완료 후 최종 답변 | 200 / 200 | 200 / 800 | 0 |
| 배포 빌드, 데스크톱 1000px | 200 / 200 | 200 / 800 | 0 |
| 배포 빌드, 모바일 380px | 200 / 200 | 200 / 800 | 0 |

브라우저 검사는 고정 응답을 실제 앱에 전달했다. 각 행의 수식 원문, 번호·분야·마지막 열, 수식 표시 영역의 존재, 셀의 세로 영역 안에 조판되는지, 마지막 열까지 가로 스크롤할 수 있는지와 페이지 넘침을 검사했다. 브라우저 콘솔 오류도 없었다. 50·100·150·200개 단위로 스트리밍을 진행하고, 미리보기와 최종 답변을 각각 전수 검사했다.

데스크톱·모바일에서 첫 행·100번째 행·200번째 행 부근 화면을 저장하고 대표 화면도 확인했다. 모바일의 넓은 표는 표 내부의 가로 스크롤로 나머지 열을 볼 수 있다.

## 발견한 결함과 수정

134번 수식에서 백슬래시 대신 원화 문자가 들어온 공백 명령이 원화 문자로 남았다. 수학 기호 앞의 제어 공백을 정규화하도록 수정했다. 원화 금액 표기는 보존하는 회귀 검사도 추가했다.

## 다시 실행

`frontend` 디렉터리에서 실행한다. UI와 배포 검사는 Chrome이 필요하다.

```sh
node --test test/latex-table-200.test.js
node --test --test-name-pattern='200개 수식 표' test/ui/ui.test.mjs
npm run test:production
```

위 검사는 모두 통과했고, 전체 프런트엔드 단위 테스트도 **170개 통과**했다. Markdown 파일과 코퍼스가 일치하는지도 테스트에서 검사하므로 파일만 바꾸어 검증 입력과 달라지는 것을 방지한다.
