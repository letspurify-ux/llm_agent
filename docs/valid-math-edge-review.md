# 정상 입력의 수식 경계 검증

2026-09-08. 손상된 수식을 추측해서 복원하는 경우보다, 유효한 수식이 정상적인 Markdown 구조에 놓였을 때 실패하는 경우를 우선 조사했다.

## 재현한 문제

1. **깊은 목록 안의 인용문에서 여러 줄 수식이 변형됨.** 인용문 앞 들여쓰기를 3칸까지만 제거해서 `>`가 수학 기호로 조판되었다. `gather`, `aligned`, `\(…\)`, `\[…\]`에서 확인했다. 실제 AST의 인용 깊이에 맞춰 들여쓰기를 처리하도록 수정했다. 수식 본문의 부등호 `>`는 유지한다.
2. **참조형 링크 안의 수식이 원문으로 노출됨.** 참조 노드 전체를 보호하던 처리를 링크 라벨과 식별자 영역으로 나눴다. 축약·생략 참조는 원래 식별자를 명시한 참조로 보존하여 수식 임시 토큰 때문에 주소·제목을 잃지 않게 했다. 식별자는 이스케이프가 해제된 표시용 label이 아닌 parser의 identifier를 사용한다.
3. **인용문 안에서 다음 줄로 분리된 식 번호가 노출됨.** 같은 컨테이너의 줄바꿈·인용 접두사는 공백으로 판정해 앞 수식에 연결한다. 다른 목록 항목·인용문의 기호를 가져오는 것은 차단한다.
4. **소수점이 있는 번호 수식이 누락됨.** `x=1.25 \tag{D}`의 소수점을 문장의 마침표로 오인했다. 정수·소수 부분을 구분하여 문장 판정에서 제외했다.
5. **긴 일반 텍스트에서 식 번호 탐색이 과도하게 느려짐.** `=`가 반복될 때 식 전체를 읽는 정규식의 역추적 비용이 길이의 제곱으로 늘었다. 번호 접미사를 먼저 찾는 방식으로 변경했다. 7만 자 텍스트를 별도 프로세스의 3초 제한 안에서 실제 렌더링하는 회귀 검사를 추가했다.
6. **좁은 수식 영역에서 식 번호가 본문과 겹침.** 원문과 DOM 개수 검사는 통과했지만 대표 화면 확인에서 발견했다. KaTeX의 절대 위치 번호가 가로 폭 계산에서 빠져 있었다. 생성된 수식 HTML에서 본문과 번호를 분리하고 grid로 각각의 폭을 확보했다. 부족한 폭은 기존 수식 영역의 가로 스크롤로 읽을 수 있다. 실제 좌표를 검사해 본문과 번호 사이에 간격이 있는지 확인한다.

기본 조합 70종에서 수정 전 **34종 실패**를 재현하고 같은 검사의 통과를 확인했다. 이후 이스케이프·엔터티·대문자 명령·여러 줄 참조 식별자를 포함해 **78종**으로 확장했다.

## 검증 구성

- 정상 입력 78종을 각각 LF·CRLF로 검사한다. 수식 원문이 정확히 일치해야 하고, 인용문·번호 목록·일반 목록 구조와 링크 주소·제목이 보존되어야 한다.
- 78종을 하나의 긴 답변으로 합쳐 서로의 수식과 참조 정의를 침범하지 않는지 확인한다.
- 기존 수식 24종을 참조 링크, 체크 목록, 각주, 취소선, 굵게, 기울임과 조합한 **144개 경우**를 추가 검사한다. 화학식·단위·행렬·정렬 환경과 TeX 내부의 Markdown 기호도 포함한다.
- 실제 Chrome의 320·1000px 화면에서 78개 구역을 각각 전수 검사한다. 수식 표시 영역이 존재하고, 페이지가 옆으로 넘치지 않아야 한다.
- 번호가 있는 수식은 본문의 오른쪽 끝과 번호의 왼쪽 시작을 직접 비교한다. 겹침 회귀 검사가 수정 전 실패하는 것을 확인하고 수정 후 대표 화면도 다시 확인했다.
- 참조 정의가 늦게 도착하는 스트리밍 미리보기와 최종 답변을 모두 검사한다.
- 배포 빌드에서는 320·380·1000px에서 같은 78종을 검사한다.
- 기존 수식 200개 표와 복합 콘텐츠·스크롤·터치·인쇄·입력·외부 요청 관련 회귀 검사도 함께 실행한다.

## 실행

최종 결과: 단위 검사 **264개**, Chrome UI 검사 **81개**, 배포 빌드 검사 **2개**, 합계 **347개 모두 통과**. 실패·건너뜀은 없다. 정상 입력 78종의 수식 원문·구조·링크·번호 간격을 전수 확인했고, 대표 화면도 육안으로 확인했다. 기존 표의 수식 **200/200개**도 다시 통과했다.
