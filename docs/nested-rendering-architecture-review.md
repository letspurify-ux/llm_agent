# 중첩 렌더링 경계와 공통 수식 엔진 검토 — 2026-09-09

## 문제의 공통 원인

기존 조합 검사를 유지한 채 추가 검토했다. 결함은 단순히 특정 TeX 명령을
모르는 문제가 아니라, 바깥 문법의 범위를 확정하기 전에 안쪽 문법을 처리하는
순서와 서로 다른 수식 구현이 남아 있는 데서 발생했다.

| 재현 입력/경로 | 수정 전 결과 |
|---|---|
| `A["$$unfinished"] --> B["$$x^2$$"] --> C` | 첫 달러와 B의 여는 달러가 한 수식이 되어 B와 연결을 삭제 |
| 접근성 제목·주소의 미완성 `$$` 다음에 정상 수식 라벨 | 메타데이터와 라벨을 합치거나 직렬화 개행을 복원하지 않음 |
| 단일 따옴표 shape의 미완성 `\frac{1` | shape의 닫는 중괄호를 TeX 인자로 빌려 읽음 |
| 연결선의 긴 수식과 320px 표 셀 | 노드만 측정하므로 연결선 MathML이 읽기 크기 아래로 축소 |
| 시퀀스 메시지의 `$$x^2+\verb\|$$\|$$` | Mermaid 내부의 별도 정규식이 verb 안의 달러에서 끊어 그림 전체 실패 |
| 클래스·상태도 수식 안의 `\text{a<br>b}` | 수식 해석 전에 br을 개행으로 바꾸어 원문 글자를 잃음 |
| 개발용 의존성 사전 번들 | 어댑터를 수정해도 캐시의 이전 수식 구현이 계속 실행됨 |

verb 재현의 실제 TeX는 `x^2+\verb|$$|`이다. 위 표의 파이프 이스케이프는
Markdown 표의 열을 보존하기 위한 표기다.

## 최종 구조

| 단계 | 책임과 불변 조건 | 구현 |
|---|---|---|
| Markdown·코드·표·주소 분리 | 기존 AST가 정한 컨테이너와 원문 좌표를 보존 | 기존 shared/remark 경계 모듈 |
| 직렬화 복원 | 언어를 명시적으로 전달. Mermaid 수식의 원문과 바깥 개행을 같은 범위 분석으로 구분 | `shared/serialized-markdown.mjs`, `shared/mermaid-math-spans.mjs` |
| 흐름도 TeX 확장 | 내용 삭제 없이 달러 구분자만 표시하여 실제 Mermaid 파서가 소유 라벨을 판정. 같은 라벨 안의 구분자만 결합 | `frontend/src/mermaid-math.js` |
| TeX 구두점이 포함된 확장 문법 | 공통 범위 분석에서 문자열·괄호·문장 경계를 먼저 보존하고 실제 파서가 라벨 역할을 재확인 | 같은 모듈과 `shared/mermaid-math-spans.mjs` |
| 그래프 보존 | 파서가 확인한 원문과 치환 결과의 노드 ID·형태, 연결 방향·종류, 그룹 구성 대조. 불일치 결과를 게시하지 않음 | `prepareMermaidMath`의 topology 검사 |
| Mermaid 내부 수식 | 파서가 이미 나눈 라벨을 본문과 같은 TeX 경계·KaTeX 옵션으로 렌더. 수식 안의 br을 줄로 나누지 않음 | `frontend/src/mermaid-native-math.js` |
| 오류 격리 | 실패 수식은 해당 라벨의 안내와 펼칠 수 있는 원문으로 남김. 반복 측정의 오류 중복과 다음 그림으로의 누적을 방지 | 렌더 컨텍스트와 `Mermaid.jsx` |
| 화면 크기 | 노드·연결선·그룹·MathML을 함께 측정하고 읽기 크기 이하는 가로 스크롤로 보존 | `Mermaid.jsx` |

TeX 주석·이스케이프·verb의 닫는 구분자 처리는 본문과 같은
`closingMathDelimiter`를 사용한다. 스캔 길이 상한을 유지하며, 완성된 TeX 그룹은
한 번의 순회로 계산해 미완성 중괄호의 반복 탐색을 피한다.

## 라이브러리 연결과 재발 방지

Mermaid 11.17.2에는 수식 렌더러를 주입하는 공개 설정이 없다. 그림 종류별로
TeX를 다시 변환하는 대신 `frontend/mermaid-math-adapter.mjs`에서 공통 수식 함수와
그 이전의 라벨 개행 변환을 명시적으로 연결했다. 설치 파일을 직접 변경하지
않고 Vite의 개발 사전 번들과 배포 변환에 동일하게 적용한다.

연결 조건은 다음과 같다.

- Mermaid를 검증한 정확한 버전으로 고정한다.
- 공통 함수와 라벨 호출 지점이 각각 하나인지 검사한다. 버전·함수 형태가
  달라지면 빌드 시작 단계에서 실패하며 이전 정규식으로 조용히 돌아가지 않는다.
- 변환 결과의 해시를 사전 번들 캐시 키에 포함한다. 실제 캐시에서 이전
  `node.label.replace(...)`가 남는 것을 재현했고, 수정 후 올바른 호출로 바뀐 것을 확인했다.
- 기존 Mermaid sanitizer는 수식 렌더 뒤에 그대로 실행한다. KaTeX의 `trust: false`,
  확장량/크기 제한, DOMPurify의 자원 태그 차단, 링크 처리, CSP를 유지한다.
- Mermaid의 전역 설정과 오류 컨텍스트는 기존 직렬 렌더 큐 안에서 적용하고
  성공·실패 모두 정리한다.

따라서 라이브러리 업데이트 시에는 의존성 버전과 어댑터를 함께 검토하고 아래의
필수 회귀 명령으로 개발·배포 결과를 확인해야 한다.

## 검증

- 기존 Markdown·LaTeX·차트·Mermaid 교차 조합, 200개 수식 표, 참조 링크,
  조회 주입, 셀 내 다단 목록·인용·각주·스트리밍·리셋·재시도 검사를 유지했다.
- 흐름도 30개와 네이티브 다이어그램 10개를 컨테이너 5종 × 실제 개행 3종 ×
  코드펜스/직렬화 셀 2종으로 조합한다. 1,200개 입력의 원문·코드 노드·이웃 셀을 대조한다.
- 미완성 달러/인자 3종 × 컨테이너 6종 × TeX 6종 × 개행 3종 × 앞뒤 배치 2종:
  648개 입력에서 정상 수식과 비수식 원문의 보존을 확인한다.
- 직렬화 72개 입력에서 LF/CRLF/br 형식, 정상 `\nleqq`, 문자 br, verb 달러를 대조한다.
- 네이티브 엔진의 MathML을 본문 엔진과 대조하고, 오류 중복·컨텍스트 정리,
  파서 구조 변조 거부, 어댑터 연결 지점 변경 시 실패를 검사한다.
- 실제 앱에서는 목록 → 인용 → 표 → 목록 → 그림 → TeX와 차트·이웃 셀을
  1,000px/320px에서 검증한다. 흐름도·시퀀스·상태·클래스의 정상/오류 라벨,
  MathML 의미·분수·크기, 링크·접근성 제목, 목록 기호 좌표, 넘침, 콘솔을 검사한다.
- 스트리밍 검사는 정상/오류 흐름도, 미완성 라벨과 정상 shape 수식, 시퀀스,
  여러 줄 수식, 차트를 함께 받는다. 완료 후 그림 5개·수식 5개·원문 안내·
  이웃 셀과 홈 리셋을 확인한다.
- 실제 자원 요청 검사는 흐름도·시퀀스·상태·클래스의 수식/일반 라벨에서
  이미지 요청과 DOM 이미지 요소가 모두 0개인지 확인한다.

실행 명령:

```sh
npm --prefix backend test
npm --prefix frontend run test:regression
```

최종 결과: 백엔드 전체 569개, 프런트엔드 단위 327개, Chrome UI 88개,
production 3개가 통과했다. 실패·취소·건너뜀은 모두 0개다. 필수 회귀 실행기는
백엔드 경계 144개를 포함해 562개이며, production에는 실제 앱 124회 조합이 포함된다.
개발 화면 120회와 추가 UI 6개도 통과했다.

마지막 어댑터 경로 정규화 후, `/`·`\` 경로의 개발/배포 연결과 변경 감지를
포함한 어댑터 단위 3개 및 production 3개(124회 화면 조합 포함)를 재실행해
모두 통과했다. 상태도 수식 안의 `a<br>b`가 실제 글자로 보이는 데스크톱·모바일
배포 캡처도 확인했다. `git diff --check`가 통과했고 임시 probe는 제거했다.

중간 실행에서 발견한 실패도 판정에 반영했다. 샌드박스 안의 일반 단위 실행은
로컬 포트 생성 제한 때문에 3개가 실패했고, 필요한 실행 환경에서 전체 검사를
다시 통과했다. 실제 화면에서는 연결선 글자 크기, 상태도의 HTML 수식 경로,
네이티브 라벨의 br 변환, 개발 캐시 잔존을 추가 재현하여 각각 수정했다.
정상 수식·이웃 콘텐츠·화면 크기 판정을 완화해 통과시키지 않았다.

기존 문법 자체가 잘못된 Mermaid는 원문 코드로 남고, 지원하지 않는 TeX를
추측해 다른 수식으로 바꾸지 않는다. 입력의 의미를 유지하는 중첩 렌더링과
오류 격리를 검증한 결과이며, 정의되지 않은 임의 문법을 새로 유추하는 기능은 아니다.
