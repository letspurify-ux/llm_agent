# Mermaid 연결·서식·수식 중첩 검토 — 2026-09-09

현재 작업 트리의 기존 수정과 전체 회귀 결과를 확인한 뒤, 실제 그림 안의
연결 문법·라벨 서식이 수식 지원에 영향을 주는 경계를 추가 검토했다.

## 재현한 결함과 수정

| 조합 | 재현 결과 | 수정 |
|---|---|---|
| 수식 라벨 + 양방향 화살표 `<-->`·`<==>` | 정상 그림이지만 수식이 달러 원문으로 남음 | 그림 전체의 `<` 문자로 수식 지원을 끄던 판정 제거 |
| 수식 라벨 + 여러 노드의 `&` 연결 | 수식 MathML이 0개가 됨 | 연결 문법과 HTML 처리를 분리 |
| 수식 라벨 + `<br/>`·문자 참조 | 줄바꿈·문자 표기가 다른 라벨의 수식까지 끔 | 라벨의 위험 요소는 잠긴 DOMPurify 설정으로 제거하고 수식은 유지 |
| 방향을 생략한 `flowchart`, 다른 그림 안의 `flowchart LR` 예시 | 실제 그림 종류와 수식 렌더 경로가 어긋남 | Mermaid의 `detectType`으로 실제 종류를 판정. 실제 개행도 Mermaid와 같이 정규화 |
| 주석·frontmatter·지시문 안의 수식 예시 | 전체 문자열 치환이 예시를 실행. 미지원 명령 하나가 정상 그림을 원문 폴백으로 바꿈 | Mermaid가 본문에서 제외하는 범위를 먼저 가려 실제 표현식만 변환 |
| 표 → 목록 → Mermaid의 실제 화면 | 목록 기호가 그림 맨 아래 기준선으로 내려감 | SVG를 블록으로 배치해 기호가 목록의 첫 줄에 정렬되도록 수정 |

수정 전 실제 Chrome에서 양방향 연결·여러 노드 연결·줄바꿈·문자 참조의
4개 사례 × 2개 화면 폭이 모두 실패했다. 굵은 Markdown 라벨 대조군 2회는 통과했다.
실패 판정은 그림이 존재하는지와 별개로 해당 SVG 안의 MathML 개수가 0인 것이었다.
메타데이터 원문을 기존 전체 문자열 치환에 넣었을 때도 `\unknown`의 KaTeX 오류를 재현했다.

문법은 [Mermaid 공식 흐름도 문서](https://mermaid.js.org/syntax/flowchart)와 설치된
Mermaid의 `preprocess`, `frontmatter`, `comments`, `createText`, `sanitizeText` 구현을
확인했다. 지원 범위는 정상 연결·Markdown 라벨·수식의 조합이며, 라이브러리가
지원하지 않는 수식·그림은 원문 폴백으로 남긴다.

## 구현과 검증

- [mermaid-math.js](../frontend/src/mermaid-math.js)는 제외 범위를 원문과 같은 길이로 가려 수식의 정확한 위치와 나머지 원문을 유지한다.
- [Mermaid.jsx](../frontend/src/Mermaid.jsx)는 각 그림의 기본 설정 복원·종류 판정·수식 변환·렌더를 같은 직렬 작업에서 수행한다. 일반/수식 라벨 모두 자원 요소와 속성을 제거하는 설정을 사용하며, 본문 지시문이 이를 덮어쓰지 못한다.
- [mermaid-math.test.js](../frontend/test/mermaid-math.test.js)는 정상 그림 8종 × Markdown 컨테이너 5종 × 실제 개행 3종 × 표 안/밖 2종 = 240개 원문 조합을 대조한다. 메타데이터 3종 × 개행 3종의 치환 위치·원문 보존과 실제 그림 종류도 확인한다.
- [실제 앱 검사](../frontend/test/review/rendering-browser.mjs)에 새 그림 8종을 `인용 → 번호 목록 → 표 → 목록 → Mermaid → 수식/서식`으로 넣었다. 1,000px·320px에서 MathML의 내용·실제 크기, 노드 수, 굵은 글씨, 라벨 문자열, DOM 부모 구조, 이웃 셀, 넘침, 콘솔, 임시 토큰을 검사한다. Chrome의 `::marker` 레이아웃 좌표도 읽어 목록 기호와 그림 시작점이 정렬되는지 확인한다. 기존 38회와 합해 54회다.
- [Chrome UI 검사](../frontend/test/ui/ui.test.mjs)는 수식/일반 라벨의 HTML 이미지·Markdown 이미지·인코딩한 이미지·CSS URL·설정 덮어쓰기 7개 그림이 모두 수식으로 표시되면서 이미지 요소와 자동 요청이 0인지 확인한다.

새 검사는 기존 필수 회귀 실행기와 production 검사에 포함된다. 기존 수식 표 200개,
표 링크·중첩 조합·조회 주입·스트리밍·리셋·재시도·인쇄 검사도 유지한다.

```sh
npm --prefix backend test
npm --prefix frontend run test:regression
```

실제 DB·LLM은 고정 응답으로 대체해 렌더링과 조회 주입 경계를 검증한다.

단위 검사 316개, Chrome UI 87개, production 3개가 모두 통과했다(총 550개).
실패·취소·건너뜀은 0개다. 별도 백엔드 전체 검사도 569/569개가 통과했다.
