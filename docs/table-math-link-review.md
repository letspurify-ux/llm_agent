# 표·수식·참조 링크의 경계 검사

2026-09-08. 절댓값·행렬 수식에 Markdown 링크를 붙이고 그 링크를 표 셀에 넣는 조합에서 두 가지 실패를 재현했다.

| 입력 형태 | 발견한 문제 |
|---|---|
| `[$|x|$][]`, `[$|x|$]` | 수식은 조판되지만 참조 링크가 사라짐 |
| `[$|x|$][ref]` | 뒤의 `[ref]`를 별도 링크로 읽어 링크가 중복됨 |

## 원인과 수정

첫 Markdown 파싱은 수식 내부의 `|`에서도 표 셀을 나눠 링크 전체를 놓쳤다. 이후 수식을 보호해 표를 다시 파싱해도 이미 누락되거나 부분적으로 읽은 참조 정보를 복구하지 못했다. 식별자에 원래 수식을 그대로 넣으면 식별자 안의 `|`가 표를 다시 나누는 문제도 있었다.

표 구분 행만 길이가 같은 공백으로 바꾼 분석에서 링크의 원문 좌표를 보충한다. 실제 출력할 표와 수식은 원문을 사용한다. 부분 링크에서 만든 보정은 폐기하고, 참조 식별자는 표 문법과 충돌하지 않는 임시 별칭으로 처리한다. 별칭의 정의에는 최초 파싱에서 얻은 원래 URL·제목을 연결하므로 URL을 Markdown 문자열로 재조립하지 않는다. 참조 정의의 첫 선언 우선 규칙도 유지한다.

별칭 정의는 앞에 두어 스트리밍 답변 끝의 미완성 코드 펜스에 삼켜지지 않도록 했다. 겹치는 주소·코드 보호 범위는 병합하여 경계 탐색을 유지한다. 실제 링크의 URL 검증과 외부 이미지 차단은 기존 렌더러를 그대로 거친다.

## 검증 범위

- 절댓값, `\left|…\right|`, 세로 구분선이 있는 `array` 수식 3종.
- 수식만 있는 라벨, 설명을 포함한 라벨, 굵게 표시한 라벨 3종.
- 완전 참조·축약 참조·생략 참조·인라인 링크 4형식.
- 본문·인용문·번호 목록·목록 안의 목록과 인용문·인용문 안의 목록 5구조.
- LF·CRLF 2형식으로 본문 셀 **360개 조합**, 머리글 셀 **360개 조합**, 합계 **720개 조합** 검사.
- 이 조합을 묶은 **180개 표**에서 수식 원문, 링크 개수·주소·제목, 이웃 셀을 검사.
- Chrome의 320·1000px 화면에서 모든 표의 실제 조판 영역과 마지막 열의 스크롤 접근성을 검사.
- 참조 정의가 나뉘어 도착하는 스트리밍, 뒤에 미완성 코드 펜스가 붙는 경우, 최종 답변을 각각 검사.
- 배포 빌드에서도 같은 180개 표를 검사하고 기존 수식 200개 표 및 전체 회귀 검사를 실행.

입력은 [table-link-edge-corpus.js](../frontend/test/table-link-edge-corpus.js), 화면 검사는 [table-link-checks.mjs](../frontend/test/ui/table-link-checks.mjs)에 있다.

최종 결과는 단위 검사 **272개**, Chrome UI 검사 **84개**, 배포 빌드 검사 **2개**, 합계 **358개 모두 통과**다. 실패·건너뜀은 없다. 기존 수식 200개 표도 다시 통과했다. 모바일의 깊은 중첩 표를 스크린샷으로 확인했으며, 수식이 링크로 표시되고 이웃 셀이 유지됐다.

`frontend`에서 다음 명령으로 실행한다. UI 검사는 Chrome 및 로컬 서버 실행 권한이 필요하다.

```sh
npm test
npm run test:ui
npm run test:production
```

이 검증은 위 조합의 내용·링크·표 구조 보존을 확인한다. 임의의 모든 LaTeX·Markdown 입력에 대한 무결성을 뜻하지 않는다.
