# Mermaid 라벨과 리터럴의 문법 경계 검토 — 2026-09-09

현재 작업 트리의 공통 수식·백틱·직렬화·표 셀 처리와 회귀 검사를 다시 확인하고,
Mermaid 내부에서 수식 라벨과 다른 문자열이 섞이는 경계를 보완했다.

## 재현한 문제와 수정

`A["$$x^2$$"]`와 `click A "https://example.test/$$x$$" "원문 $$\unknown{x}$$"`가
함께 있으면, 기존 전체 문자열 치환은 주소까지 MathML로 바꾸고 툴팁을 KaTeX에
전달했다. 실제 production Chrome에서 툴팁의 미지원 명령 때문에 정상 그림
전체가 코드 폴백으로 남는 것을 재현했다.

[Mermaid 공식 문법](https://mermaid.js.org/syntax/flowchart.html)의 노드·연결선·하위
그래프 라벨과 click의 주소·툴팁은 서로 다른 문법 자리다. 별도의 정규식으로
각 문법을 다시 구현하지 않고, [mermaid-math.js](../frontend/src/mermaid-math.js)의
`prepareMermaidMath`가 수식 후보를 충돌 없는 토큰으로 가려 실제 Mermaid 파서에
전달한다. 파서가 만든 노드·연결선·하위 그래프의 라벨에서 확인한 후보만 변환한다.
주소·툴팁·접근성 설명·스타일·식별자는 원문을 유지한다. 라벨이 생략된 노드의
식별자는 HTML로 바꾸지 않고 Mermaid 자체 라벨 조판에 맡긴다.

shape 속성의 작은따옴표 라벨도 검사했다. 기존 MathML의 속성 따옴표가 바깥
YAML 문자열을 닫고, 수식 annotation의 `^`·중괄호·백슬래시가 Mermaid 문법과
충돌했다. 추가 완료 점검에서는 수식 설명의 쉼표·콜론·대괄호도 YAML 구분자가
되는 것을 재현했다. KaTeX가 생성한 HTML의 속성·문자 값은 유지하면서 문장부호를
Mermaid의 숫자 문자 참조로 표현하도록 통일했다. 기존 HTML 문자 참조도 같은
값의 Mermaid 표기로 옮겨 앰퍼샌드가 중복되지 않게 한다.
실제 HTML 파싱 결과의 수식 트리·속성·문자가
원래 MathML과 동일한지 15개 수식으로 비교한다. 큰따옴표·작은따옴표·평문 shape 라벨을 실제
그림으로 확인한다.

복합 수식의 `\text{…\$\$d\$\$…}`도 실제 Chrome에서 확인했다. Mermaid가
디코딩한 MathML 텍스트를 다시 수식으로 처리해 달러 문자가 사라지고 두 번째
MathML이 생기는 결함을 재현했다. Mermaid 자체 수식 처리와 같이 대체 원문
annotation을 제외하고, 연속 달러만 같은 그룹 안의 인접 MathML 텍스트로 나누어
글자·서식을 유지하면서 다시 구분자가 되지 않도록 했다. 수식 개수와 설명의
정확한 문자, 분수 개수·실제 크기를 함께 검사한다.

[Mermaid.jsx](../frontend/src/Mermaid.jsx)는 후보 파싱·기본 설정 복원·최종 렌더를
기존 직렬 작업 안에서 수행한다. 후보만 있고 실제 라벨 수식이 없으면 기존
일반 라벨 설정으로 그린다. HTML 자원 요소·속성 제거와 설정 잠금은 유지한다.

## 검증 범위

- Mermaid 코퍼스를 8종에서 18종으로 확장했다. 주소·툴팁·접근성 설명, 세 가지
  shape 라벨, 연결선·하위 그래프·따옴표 없는 라벨, 수식이 없는 대조군, 토큰 모양 원문을 포함한다.
  shape 수식은 분수·문장부호·수식 내부의 달러 문자 예시를 함께 포함한다.
- 18종 × Markdown 컨테이너 5종 × 실제 개행 3종 × 표 안/밖 2종 = 540개 입력의
  정확한 그림 원문과 이웃 셀을 비교한다.
- 실제 앱에서는 `인용 → 번호 목록 → 표 → 목록 → Mermaid → LaTeX`로 검사한다.
  기존 차트·조회·각주·수식·문자 출처 사례와 합쳐 37종 × 화면 폭 2종 = 74회다.
- 화면 검사는 SVG·MathML 개수에 더해 수식의 내용·크기, 노드 수, 굵은 글씨,
  링크 주소, 접근성 제목, 목록 기호 좌표, 컨테이너·이웃 셀, 페이지 넘침, 콘솔을 확인한다.
- 최종 개발 화면 검사 74/74회가 통과했다. 1,000px와 320px의 캡처에서 분수·설명·
  달러 문자가 섞인 shape 수식과 목록 배치를 직접 확인했고, 표를 끝까지 스크롤한
  캡처에서 마지막 RIGHT 셀을 확인했다. 모든 사례의 페이지 가로 넘침은 0px다.

주요 검사는 [mermaid-math.test.js](../frontend/test/mermaid-math.test.js),
[브라우저 조합 검사](../frontend/test/review/rendering-browser.mjs),
[production 검사](../frontend/test/ui/production.test.mjs)에 있으며 필수 회귀 실행기에 포함된다.
실제 DB·LLM 대신 고정 응답과 조회값을 사용한다. 라이브러리 미지원 문법의 원문
폴백과 기존 오류 격리·스트리밍 검사는 유지한다.

중간 검사의 접근성 설명 예제에는 Mermaid가 닫는 기호로 읽는 중괄호가 설명
안에 들어 있었다. 설치된 파서 규칙을 확인하고 유효한 설명으로 고쳤으며,
주소·제목·수식·그림의 실제 판정은 유지했다.

## 최종 검증

실행 명령은 `npm --prefix backend test`와
`npm --prefix frontend run test:regression`이다.

최종 소스를 고정한 필수 회귀 실행에서 백엔드 경계 144개, 프런트엔드 단위
317개, Chrome UI 87개, production 3개가 모두 통과했다(총 551개).
실패·취소·건너뜀은 0개이며, production에는 위의 실제 화면 74회 검증이 포함된다.
별도 백엔드 전체 검사도 569/569개가 통과했다.

| 요구 동작 | 확인한 증거 |
|---|---|
| Markdown·LaTeX·chart·Mermaid의 중첩 구조와 원문 보존 | 공통 문법 경계 및 nested-boundaries·syntax-ownership·cell-blocks·mermaid-math 조합 검사 |
| 서버 조회와 화면이 같은 코드·수식·표 경계를 사용 | 백엔드 chart·markdown-syntax 검사와 실제 조회값을 넣은 단위/배포 검사 |
| 오류·미완성 입력이 이웃 콘텐츠를 삼키지 않음 | 수식 오류 원문·모든 스트림 접두사·리셋·재시도·홈 이동 UI 검사 |
| 실제 수식·그림·서식·주소·이웃 셀을 읽을 수 있음 | 개발/배포 74회 검사에서 내용·크기·연결·부모 구조·스크롤·콘솔 판정 및 캡처 확인 |
| 모바일·인쇄·배포에서 회귀 없음 | Chrome UI 87개와 현재 소스를 새로 빌드한 production 3개 |
| 수식 변환 후에도 자동 자원 요청 제한 유지 | 수식/일반 라벨의 이미지·CSS·설정 덮어쓰기 검사 통과 |

양쪽 package/lockfile 의존성 대조, 프런트엔드 offline 설치 계획 확인,
`git diff --check`도 통과했다. 최종 실행 전후 핵심 소스와 테스트의 SHA-256을
대조해 실행 중 변경이 없음을 확인했다.

수정을 계속하던 중간 전체 실행에서는 패널 펼침 위치 검사 1건이 실패했다.
최종 소스를 고정한 전체 재실행에서 해당 검사와 나머지 UI·배포 검사가 모두
통과했다. 검사 조건·시간 제한은 완화하지 않았다.
