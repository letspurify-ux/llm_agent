# 직렬화된 표의 행 경계와 원문 보존 검토 — 2026-09-09

## 추가로 확인한 결함

기존 표 구조 수정과 회귀 검사를 유지한 상태에서, 물리적 개행과 문자 `\n`으로
직렬화한 개행의 결과를 대조했다. 직렬화된 문서는 첫 파싱 시 한 문단이므로,
서로 다른 표 행의 미완성 링크·이미지·수식이 하나의 원자로 인식됐다. 그 범위를
개행 복원에서 보호하면 뒤의 표 행까지 한 줄에 갇혔다. 차트 조회가 주입되지
않거나, 수식·Mermaid·오른쪽 셀 내용이 표시에서 사라지는 것을 재현했다.

실제 개행에서는 앞선 [표 구조 분석](rich-table-structure-review.md)이 행별로
소유 범위를 다시 확인했지만, 개행을 복원하는 단계에는 같은 원칙이 빠져 있었다.

## 수정 원칙

[직렬화 복원](../shared/serialized-markdown.mjs)도 다음 순서로 처리한다.

1. 원문 길이를 유지하는 구조 투영에서 표를 발견한다. 명시된 시각화의 내부
   개행은 보존하고, 수식의 파이프가 바깥 열을 늘리지 않도록 가린다.
2. GFM 파서로 행·열·컨테이너 경계를 확인한다. 새로운 행이 독립된 표의 열
   구조를 갖추었는지 확인하여, TeX 제어 단어를 나눈 조각과 구분한다.
3. [공통 구조 분석](../shared/rich-table-structure.mjs)의 `tableOwnership`으로
   원문을 확정된 셀별로 다시 읽는다. 원자가 확정된 셀 경계를 넘어가면 그 소유 범위를
   폐기한다. 참조 정의만 공유하며, 값과 치환 좌표는 원문에서 가져온다.
4. 이 범위를 기준으로 문서 개행을 복원한다. 그 뒤 서버 조회와 화면 파싱이
   같은 실제 Markdown을 받는다.

머리글·구분 행 전체를 소유한 일반 코드나 링크는 문서의 리터럴 컨테이너다.
그 안의 표 예시를 새 표나 실행할 차트로 승격하지 않는다. 이미 표 셀 안에서
시작한 원자에는 표의 행·셀 경계를 적용한다. 행에서 셀로 확장한 후속 검토는
[셀 소유 범위 기록](cell-ownership-review.md)에 정리했다.

TeX 내부의 `\nleqq`, `\nVdash`, 사용자 매크로 `\n`·`\nMATH`를 개행으로
바꾸지 않는다. 새 명령 이름을 예외 목록에 추가하지 않았다. 완성된 TeX 인자는
그룹 경계로 보호하고, 수식에서 떨어진 조각이 실제 표 행인지 확인한다.

완성된 그룹은 [공통 TeX 모듈](../shared/tex-environments.mjs)의 `texGroupEnds`가
한 번의 순회로 계산한다. Mermaid 라벨 분석도 이 함수를 사용한다. 이스케이프·
주석·verb의 경계가 같고, 미완성 중괄호마다 나머지 원문을 다시 탐색하지 않는다.

## 검증 범위

[새 회귀 검사](../frontend/test/serialized-boundaries.test.js)는 정상 개행으로
렌더링한 기준 결과를 먼저 검증한 뒤 직렬화 결과와 대조한다.

| 검사 | 범위 | 판정 |
|---|---:|---|
| 행 경계를 넘는 원자 | 10종 × 머리글 4종 × 컨테이너 5종 × 가장자리 4종 × 개행 2종 = 1,600개 | 복원 원문·서버 조회 결과·최종 HTML·미리보기 일치 |
| TeX 제어 단어·매크로 | 320개 | TeX 원문과 렌더 결과 일치 |
| 리터럴 안의 표 예시 | 6개 | 원문 보존, 표·차트 실행 없음 |
| 뒤 행을 수신하는 접두사 | 326개 | 앞 행의 수식과 이웃 셀 보존, 임시 토큰 없음 |
| TeX 그룹 경계 | 정상·이스케이프·주석·verb·미완성 그룹 | 본문 구분자 엔진과 일치, 미완성 중괄호 70,000개 처리 비용 제한 |

차트 검사는 조회 값의 파이프·달러 문자와 숫자를 포함하고, 각 행의 오른쪽
셀을 정확히 확인한다. 백엔드 문법 검사에도 조회 주입과 TeX 원문 검사를 추가했다.

[브라우저 검사](../frontend/test/review/rendering-browser.mjs)의 새 그룹은
`인용 → 목록 → 표 → 목록/인용 → 차트·Mermaid → 수식`을 포함한다. 10개
원자 사례를 1,000px·320px에서 검사한다. 실제 SVG·차트·MathML, 오류 원문,
셀 개수와 내용, 가로 스크롤로 오른쪽 셀에 도달할 수 있는지, 글자 폭,
페이지 넘침과 콘솔을 확인한다.

기존 150회 브라우저 조합과 새 20회 조합은 별도의 배포 검사로 실행한다.
둘 다 현재 소스로 새로 빌드하며, 필수 회귀 명령에 포함된다. 기존 검사와
제한 시간은 유지했다.

```sh
npm --prefix backend test
npm --prefix frontend run test:regression

# 추가한 실제 화면 조합만 확인
node frontend/test/review/rendering-browser.mjs --group=serialized-boundaries
node frontend/test/review/rendering-browser.mjs --production --group=serialized-boundaries
```

실제 DB·LLM 대신 고정 응답과 조회값으로 렌더링 경로를 검증한다. 미완성 입력과
라이브러리의 미지원 수식은 원문으로 확인할 수 있게 유지한다.

## 단계별 검증 이력

이 작업의 행 경계 수정을 적용한 소스에서 백엔드 전체 574개, 프런트엔드 단위 340개, Chrome UI 88개가
통과했다. 필수 회귀 실행기에 포함된 백엔드 전송·차트·문법 149개도 통과했다.
새 직렬화 그룹은 개발·배포 모두 20회 통과했으며, 배포 대화·전체 렌더 검사와
CSP 검사도 통과했다. 실패·취소·건너뜀은 위 검사에서 모두 0개다.

첫 전체 실행의 기존 배포 교차 조합은 150회 중 149회 통과·1회 실패했다. 자식 프로세스의 큰
JSON 출력이 Node의 오류 출력에서 잘려 사례 식별 정보가 남지 않았다. 같은
소스를 직접 실행했을 때에는 `table-structure-unclosed-code/1000`의 Mermaid
대기가 만료됐다. 해당 사례만 새 배포 빌드로 실행한 2회는 통과했다. 실패 시
DOM·코드 원문·페이지 가시성을 기록하고, 실패 식별자·판정값을 별도로 출력하도록
검사 진단을 개선했다. 판정 조건과 제한 시간은 변경하지 않았다.

이미지 원자가 행 경계를 넘던 사례의 1,000px·320px 캡처에서는 정상 수식,
차트의 실제 막대와 값, Mermaid의 수식·연결선 라벨, 오른쪽 셀을 확인했다.
소스·테스트 126개 파일의 SHA-256을 실행 시작 후 대조했을 때에는 변경이 없었다.
이후 완료 검토에서 같은 폴더의 별도 작업이 공통 표 분석·직렬화 복원·서버 조회·
화면 표 보호 파일을 수정한 것을 확인했다. 새 변경은 셀 단위 소유 범위까지
확장하는 작업이며 보존했다. 따라서 앞선 전체 통과 수치는 현재 합쳐진 소스의
검증 결과로 사용할 수 없다. 현재 문법 검사 9개는 통과했고, 배포 검사를 단독
재실행했을 때 기존 조합 150회와 새 조합 20회가 통과했다. 소스가 안정된 뒤
전체 회귀 검증을 다시 완료해야 한다.

더 넓은 완료 검토에서는 인용·목록·링크 안의 긴 인라인 수식이 모바일에서
잘리는 기존 동작도 재현했다. 이 문제는 이후 [인라인 수식 배치 개선](inline-math-layout-review.md)으로
수정했다. 현재 합쳐진 소스의 검증은 [완료 검토 기록](nested-rendering-follow-up.md)에 기록한다.
