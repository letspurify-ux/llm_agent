# Markdown·LaTeX·차트 표시 개선

## 확인한 원인

- 기존 수식 복구는 Markdown 파싱 이후 텍스트 노드를 검사했다. 그 시점에는 `\(`의 백슬래시, `_`·`*`의 강조 해석, 줄바꿈, 표 안의 `|`, HTML 엔티티가 이미 해석되어 원래 수식의 경계를 잃을 수 있었다. 따라서 명령을 정규식 목록에 추가해도 문장·표·목록마다 결과가 달랐다.
- `gather`, `split`, 식 번호 `\tag` 등은 별행 모드가 필요하다. 인라인 구분자나 구분자 없는 출력은 수식으로 발견되지 않거나 잘못된 모드로 전달됐다. 프롬프트도 `$$`를 인라인 표기로 안내하고 있었다.
- 실제 원화 문자 `₩`·`￦`는 ASCII 백슬래시와 다르다. 폰트가 백슬래시를 원화 모양으로 표시하는 경우와 별개로, 실제 원화 문자가 들어간 명령은 정규화가 필요했다.
- KaTeX 기본 로딩만으로 `\ce`·`\pu`가 등록되지 않는다. `mhchem` 확장 등록이 필요했다. `flalign`, `multline`, `subequations` 및 모델이 생성하는 철자 변형도 별도 호환 처리가 필요했다.
- 모르는 명령과 파싱 오류의 표시 경로가 달라 CSS로 원문 노출을 해결할 수 없었다. 앞의 미완성 환경이 뒤의 완성된 환경을 잘못 포함하는 문제도 재현했다.
- 백엔드 JSON 디코더와 스트림 파서는 공통 수식 코퍼스의 원문을 보존했다. 정상 JSON과 명령 백슬래시가 덜 이스케이프된 JSON을 최종 응답 및 1·7·1000자 스트림 조각으로 검사했다. 디코더 변경은 필요하지 않았다.
- 후속 신고의 `$… =`·`$… \ln`·`$… \frac{` 잘림은 표 안 절댓값 파이프와 함께 재현했다. `$\sqrt{a^2} = |a| $`처럼 닫는 `$` 앞에 공백이 있으면 기존 판정이 수식 전체를 거절했다. 잘못된 중괄호도 경계 검사 단계에서 거절했다. 그러면 GFM이 내부 `|`를 열 구분자로 읽고 헤더보다 많은 셀을 버렸다. 이전의 정상 수식 코퍼스에는 앞뒤 공백과 잘못된 중괄호를 교차한 표 검사가 빠져 있었다.

## 수정 구조

`remark-preserve-math.js`는 첫 Markdown 파싱으로 코드·링크 주소의 경계를 파악한다. 완성된 수식은 원문 좌표에서 추출하여 임시 토큰으로 보호하고 Markdown을 다시 파싱한 다음 수식 노드를 복원한다. 수식 내부의 표 구분자·강조 기호·빈 줄이 Markdown 구조를 바꾸지 않는다. 토큰은 최종 출력에 남기지 않는다.

후속 수정은 수식 구분자 인식과 TeX 문법 검증을 분리한다. 구분자 안 앞뒤 공백을 허용하고, 중괄호가 틀려도 구분자 범위 전체를 먼저 보호한다. 홑 달러는 문단·표 행을 넘어 연결하지 않는다. 명확한 TeX 입력인데 닫는 구분자가 없다면 `table-math.js`가 표의 열 수와 이웃 수식을 기준으로 원문을 셀에 격리한다. 해당 셀은 오류 원문 보기로 남기고 식의 내용을 추측해 채우지 않는다. 원화로 잘못 입력된 `\,`·`\|` 같은 제어 기호도 수식 안에서 정규화한다.

`tex-environments.js`는 중첩 환경, 주석, 이스케이프, `\verb`를 고려해 여닫는 짝과 별행 필요 여부를 판단한다. 구분자 없는 환경과 호환 변환이 같은 판정을 사용한다. 잘못된 앞 수식이 뒤의 정상 수식을 숨기지 않도록 문서 경계 복구도 처리한다.

`math.js`는 하나의 KaTeX 렌더 경로를 사용한다. `mhchem`을 등록하고 별행 전용 문법을 별행으로 승격한다. KaTeX가 생성한 HTML만 HAST로 변환한다. 미지원·잘못된 수식은 동일한 오류 안내와 접힌 원문으로 표시하며, 원문에는 정규화 이전 문자열을 보존한다. 오류 요소가 문단·링크 내부에 잘못 중첩되지 않게 분리한다.

일반 코드펜스와 인라인 코드는 원문을 유지한다. `math`·`latex`·`tex` 코드펜스는 수식으로 처리한다. 차트·흐름도 코드펜스도 보존되어 기존 컴포넌트가 처리한다. 차트의 조회 데이터는 기존과 같이 문자·수치 그대로 사용한다. 스트리밍 중 차트 준비 안내가 최종 차트로 바뀌어도 주변 수식은 같은 경로로 렌더링한다.

## 검증

- 공통 수식 24개 × 구분자 4종 × Markdown 위치 6종, 총 576개 조합을 실제 ReactMarkdown·KaTeX 렌더링으로 검증한다. 수식 원문과 표의 열 수도 대조한다.
- 표 신고 회귀 검사는 절댓값·적분·곡률 3식 × 공백 5종 × 백슬래시 3종 × 열 위치 3종 × 외곽 파이프 유무 × 헤더/본문, 540개 조합을 추가한다. 오류 입력 5종 × 열 위치 3종 × 인용·들여쓰기 3종 × 외곽 파이프 유무, 90개 조합도 검사한다. 오류 셀의 정확한 원문·이웃 셀·다음 행까지 대조한다.
- 표 전체의 JSON 전송·스트리밍, 앞의 통화 달러와 뒤 표의 수식이 연결되지 않는지, 모든 수신 접두사에서 이미 완성된 행이 유지되는지도 검증한다. 실제 브라우저·배포 번들은 동일한 표 코퍼스를 사용한다.
- 별도로 환경 10종 × 백슬래시 표기 3종 × 감싸는 형태 8종, 화학식·단위, 엔티티, 통화, 주소, 일반 코드, 인용문·목록의 빈 줄, 중첩 환경·식 번호, 잘못된 수식 이후 정상 수식을 검증한다.
- 스트리밍 입력의 모든 접두사에서 예외와 임시 토큰 누출이 없는지 검사한다. 실제 앱에서 스트리밍 미리보기와 최종 응답의 수식 원문이 같은지도 대조한다.
- 1000px·380px 브라우저 화면에서 수식·Markdown 표·차트가 섞인 답변의 표시, 차트의 표 전환, 코드 보존, 오류 원문 펼침, 가로 넘침을 확인한다.
- 전체 프런트엔드 단위 테스트와 UI 회귀 테스트, 백엔드 단위 테스트를 실행한다. 별도 production 테스트는 현재 소스를 빌드한 뒤 실제 번들에서 수식·차트 4개·흐름도·조회 표·후속 대화를 검사한다.

## 지원 범위

KaTeX는 전체 LaTeX 엔진이 아니다. `flalign`은 `align`, `eqnarray`는 `align`, `multline`·`multiline`은 `equation` 안의 `gathered`, `multlined`는 `gathered`로 호환 표시한다. 따라서 원래 LaTeX의 양끝 정렬 간격과 완전히 같지는 않다. `subequations`의 명시적 `\tag{1a}`·`\tag{1b}`는 보존하지만 자동 하위 번호는 추측하지 않는다.

환경 이름만 있는 `{gather}` 같은 설명이나 닫히지 않은 원문은 임의의 식으로 만들지 않는다. 별도로 복구하는 수식의 경계 탐색은 5000자로 제한한다. KaTeX 미지원 패키지·명령은 원문 보기로 안내한다. 이러한 입력을 임의로 삭제하거나 의미가 다른 수식으로 바꾸지 않는다.
