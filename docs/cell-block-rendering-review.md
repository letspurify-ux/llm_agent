# 표 셀 내부의 다단 블록과 조회 경계 검토 — 2026-09-09

기존 변경이 있는 현재 작업 트리에서 전체 검사를 다시 시작하고, 표 **안쪽**의
목록·인용·시각화 구조와 가장자리 셀의 서버 조회 주입을 추가로 확인했다.

## 재현과 수정

| 입력 | 재현한 결과 | 수정 |
|---|---|---|
| 표 → `<br>` → 목록 → 하위 목록 → LaTeX | 하위 목록이 부모와 같은 깊이로 펴짐 | 셀의 블록 문법을 Markdown 파서로 분석하고 기존 인라인 노드를 복원 |
| 표 → 인용 → 목록 → 번호 목록 → Mermaid | 목록 기호가 일반 글자로 남고 그림이 컨테이너 밖으로 이동 | 인용·목록 깊이와 이어지는 행을 같은 파서가 결정 |
| 표 → 목록 → 인용 → 목록 → 조회 차트 | 그림이 원래 목록에서 분리되고 중첩 그림에는 셀 폭 규칙이 적용되지 않음 | 시각화를 해당 컨테이너의 블록으로 유지하고 셀 안 모든 깊이에 폭 규칙 적용 |
| 양끝 `\|`를 생략한 GFM 표의 첫·마지막 셀 → 조회 차트 | 실제 코드로 렌더링되지만 서버가 데이터를 채우지 않음 | 파이프 유무 대신 AST 표 행 범위로 판단 |
| 표가 아닌 산문 `설명 \| 차트 코드 \| 끝` | 화면에서 코드 예시인 자리를 서버가 조회 데이터로 바꿈 | 실제 표 행과 코드 하나로 이루어진 독립 문단만 주입 대상으로 선택 |
| 직렬화된 개행 → 양끝 파이프 없는 표 → 영문 첫 셀 | `\\nLEFT`가 남아 표를 만들지 못함 | 직렬화된 구분 행을 확인해 개행 복구를 확장하고 수식·코드·주소를 먼저 보호 |
| 이스케이프된 백틱 → 독립된 직렬화 Mermaid/chart | 서버를 거치지 않으면 `<br>` 조각과 코드 원문이 남음 | 표 셀과 같은 공통 백틱 경계로 보호·복원 |
| Mermaid/chart → 직렬화 개행 → LaTeX `\nleqq`, `\nVdash`, `\text{<br>}` | 정상 명령이나 수식의 문자 `<br>`가 개행으로 바뀜 | 알려진 명령 목록에 의존하지 않고 수식 범위 전체를 보호. 서버와 화면의 시각화 개행 처리도 공유 |

셀 블록 분석에는 들여쓰기·인용·목록·제목 기호만 전달한다. 이미 해석한 수식,
코드, 링크, 일반 글자는 AST 노드로 보관하므로 문자 참조나 사용자 원문의 토큰
모양 문자열을 두 번 해석하지 않는다. 시각화 블록도 기존 인라인 서식 밖으로
분리하면서 자신이 속한 목록·인용은 유지한다.

직렬화 개행 처리는 [공통 모듈](../shared/serialized-markdown.mjs)로 옮겼다.
서버가 조회를 채울 때와 화면이 표를 만들 때 같은 원문 정규화와 구조를 사용한다.
실제 치환이 없는 서버 응답은 원문 그대로 반환한다.

## 검증

- [cell-blocks.test.js](../frontend/test/cell-blocks.test.js): 내부 컨테이너 5종 × 수식·오류 수식·차트·Mermaid 4종 × 줄바꿈 표기 3종 × 외부 컨테이너 5종 × 실제 개행 3종 = 900개 조합. 표 밖 Markdown의 목록·인용 구조 및 콘텐츠 경로와 대조한다.
- 같은 검사에서 가장자리 파이프 4종 × 셀 위치 3종 × 외부 컨테이너 5종 × 실제/직렬화 개행 5종 = 300개 조회 조합을 확인한다. 이웃 셀·수식·조회값을 검사한다.
- 스트림의 모든 접두사, 들여쓴 서식, 문자 참조, 링크 주소, 사용자 원문의 내부 토큰 모양 문자열을 별도로 검증한다.
- KaTeX가 지원하는 수식 15종 × 시각화 개행 4종 × 내부 컨테이너 5종 × Mermaid·서버 조회 차트 2종 = 600개 원문 보존 조합을 검사한다. `n`으로 시작하는 명령과 수식 내부의 `<br>`·`<br/>`·`<BR />`를 포함한다.
- [백엔드 경계 검사](../backend/test/markdown-syntax.test.js)는 산문·서식·링크 속 코드의 미주입과 직렬화 표의 정확한 TeX·주소 보존도 확인한다.
- [배포 앱 검사](../frontend/test/review/rendering-browser.mjs)에 다단 셀과 가장자리 표를 추가했다. 1,000px·320px에서 실제 DOM의 부모 목록·인용, 차트·SVG·MathML 크기, 작업 목록, 이웃 셀, 페이지 넘침, 콘솔 오류, 내부 토큰을 검사한다.
- 배포 앱에서 새로 확인한 Mermaid 명령을 실제 MathML로 렌더링하고, 수식의 `a<br>b`가 정확한 `mtext`로 남는지도 확인한다.

실행 명령:

```sh
npm --prefix backend test
npm --prefix frontend run test:regression
```

실제 DB·LLM 대신 고정 응답과 조회값으로 렌더링을 검증한다. 라이브러리가 지원하지
않는 수식·그림 문법은 원문 폴백을 유지한다.

백엔드 조회 주입·문법 경계 테스트도 필수 회귀 실행기에 포함해, 같은 입력을 로컬과
CI에서 계속 검사하도록 했다. 새 브라우저 예제의 번호 목록은 GFM 규칙에 맞춰
시작 번호 3 앞에 빈 인용 행을 둔다. 빈 행 없이 일반 문단을 3번 목록으로 끊을 수
있다고 가정했던 최초 검사의 전제를 수정했으며, 실제 구조·개수·크기 판정은 유지했다.

## 최종 실행 결과

최종 소스에서 백엔드 전체 569개, 프런트엔드 단위 310개, Chrome UI 87개,
production 3개가 모두 통과했다. 실패·취소·건너뜀은 0개다. 필수 회귀 명령에는
백엔드 전송·조회·문법 검사 144개와 프런트엔드 세 단계, 총 544개가 포함된다.
위의 추가 1,800개 조합은 단위 테스트 안에서 반복 검증하며, 배포 교차 검사는
18개 실제 앱 사례 × 2개 화면 폭 = 36회를 포함한다.

개발 화면도 1,000px·320px에서 캡처해 구조와 배치를 직접 확인했다. 두 화면 모두
페이지 가로 넘침은 0px이며, 표를 끝까지 가로 스크롤하면 마지막 셀 4개가 모두
보이는 것을 bounding box와 캡처로 확인했다. 의존성과 lockfile의 일치,
프런트엔드 `npm ci --dry-run --offline --ignore-scripts`, `git diff --check`도 통과했다.

## 문자와 블록 문법의 출처 보존 추가 검토

기존 변경을 실제 작업 트리에서 다시 검토하면서 셀 블록 재구성의 이중 해석을
재현했다. `앞<br>\- 문자 $x$`는 목록으로, `&gt; 문자`는 인용으로,
`1\. 문자`는 번호 목록으로 바뀌었다. `- &#91;x&#93; 문자`는 `[x]`가 사라지고
체크박스가 됐다. 수식·그림의 개수만 확인하면 놓치는 원문 변경이다.

[GFM 문자 참조 규칙](https://github.github.com/gfm/#entity-and-numeric-character-references)에
따라, 이미 디코딩한 문자가 블록 구분자를 새로 만들지 않도록 수정했다.
[cell-text.js](../frontend/src/cell-text.js)는 원문에 직접 쓰인 문법과 디코딩 결과를
별도 문자열로 보관한다. 수식을 보호한 문서를 파싱한 직후 출처를 기록하고,
수식 토큰 복원·셀의 줄 분할에서도 함께 자른다. `remark-rich-table.js`는 이 출처를
기준으로 목록·인용·제목·작업 목록을 구성하고, 표시할 값은 기존 AST 노드를 사용한다.
따라서 수식이 있는지, 그림을 블록으로 분리했는지에 따라 문자 의미가 달라지지 않는다.
기존 답변에 명시적으로 지원하는 `<br>` 변형과 `\>` 인용 복구는 유지했다.

추가 회귀 검사는 다음을 확인한다.

- 문자 표기 14종 × 일반 글자·정상/오류 수식·chart·Mermaid 5종 × 줄바꿈 표기 3종 × 외부 컨테이너 5종 × 실제 개행 3종 = 3,150개 입력. 실제 표시 문자열, 수식·그림 원문, 이웃 셀, 의도하지 않은 블록 및 임시 토큰 유무를 대조한다.
- 작업 목록 문자 5종 × 내부 컨테이너 5종 × 수식 유무 2종 = 50개 입력. 표 밖의 같은 Markdown을 기준으로 목록 깊이와 체크 상태를 비교한다.
- 새 복합 행의 모든 스트림 접두사에서 이미 완성된 수식·행을 보존하고 의도하지 않은 목록·인용이 생기지 않는지 검사한다.
- 실제 앱의 1,000px·320px 화면에서 문자 예시·실제 체크박스·서버 조회 차트·Mermaid 수식을 함께 검사한다. 앞선 36회에 2회를 더해 배포 교차 검사는 38회다.

새 검사는 기존 `cell-blocks.test.js`와 배포 검사에 포함되어 같은 필수 회귀 명령으로
실행된다. 문자 디코딩 의존성도 `package.json`과 lockfile에 명시했다.

최종 검증은 백엔드 전체 569개, 프런트 단위 313개, Chrome UI 87개, 배포 검사 3개가
모두 통과했다. 새 화면 판정이 차트 범례의 `ul`까지 본문 목록으로 세던 테스트 오류는
실제 DOM과 `Chart.jsx`를 확인해 수정했으며, 배포 검사 3개를 재실행했다.
마지막 출처 보존 보완 후 관련 단위 23개도 다시 통과했다.

별도 개발 화면 검사는 38/38회 통과했다. 1,000px·320px의 캡처에서 이스케이프된
문자·실제 체크박스·Mermaid의 수식·조회 차트를 직접 확인했다. 두 폭 모두 페이지
가로 넘침 0px이며, 표를 가로 스크롤하면 마지막 셀 5개가 모두 들어오는 것을
bounding box와 캡처로 확인했다. `git diff --check`, 양쪽 package/lockfile 대조,
프런트엔드 `npm ci --dry-run --offline --ignore-scripts`도 통과했다.
